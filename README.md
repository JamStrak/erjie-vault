# 二姐小金库

手机入口：<https://jamstrak.github.io/erjie-vault/>

供二姐杂货铺两位合伙人使用的单设备手机账本。先由一人记账，另一人查看导出的经营摘要或 CSV；没有账户、服务器账目数据库或实时同步。

首页同时看**累计经营盈亏**和**整摊回本差额**，再看金库账面余额、按进价计的未售库存、代收待转入、个人垫付待报销和供应商欠款。两人的正式净出资与待报销垫付分别列出，避免把个人垫资误算成共同出资。销售时填这次卖掉的商品进价：经营盈亏＝销售＋其他经营收入－已售商品成本－其他费用－报损；整摊回本差额＝销售＋其他经营收入－净进货（进货扣除退货）－其他费用，已把尚未卖出的商品进价算在投入中。已售成本清楚时，它也等于经营盈亏减去未售库存成本。合伙人入金只是钱的来源，不会再从回本差额中扣一次；回本差额为正也不代表合伙人的出资已实际返还，个人代收的销售款也可能尚未进入金库。旧账或暂不清楚成本的销售会提示“待核算”，从明细补齐后才显示准确盈亏。

金库金额不足时仍可先记金库支付的进货或经营支出，账面余额会显示负数，新增的缺口按**原支出逐笔标为“待核实付款”**。之后即使有入金，提醒也不会自动消失；在首页提醒或明细中打开归类，按实际情况将差额确认为某位合伙人垫付、供应商赊账、真实透支，或关联后来补录的实际收款。可以分次处理同一笔差额。供应商赊账与后续还款分别留痕，归类本身不会重记进货或费用。

赊账进货退货时，未付款的部分可关联原赊账直接抵减欠款；已经付款的部分按实际退款去向关联原赊账。退到合伙人手里时，明确选“个人代收、待转入金库”（默认），或经核对后选“抵扣该人的待报销垫付”；代收款实际交回金库时再记转入。

本地预览需要用下面的开发服务器打开页面；直接双击 `index.html` 的 `file://` 地址不适合记账。正式在手机上使用时，请从 iPhone Safari 打开上方网址并添加到主屏幕。之后固定从主屏图标录入，避免浏览器与主屏应用各自形成一本账。完整操作见 [使用说明.md](使用说明.md)。

账目保存在浏览器本机存储。每次出摊后导出完整 JSON，在手机“文件”中确认文件存在；CSV 和文字摘要用于合伙人核对，不能用于恢复。程序源码可以公开托管，真实账目数据无需上传到源码仓库。

本项目无运行依赖。运行 `npm test` 检查核心记账规则。开发预览可用 `python -m http.server 22861 --bind 127.0.0.1`；该本地地址只供电脑调试，不是给手机长期使用的入口。
